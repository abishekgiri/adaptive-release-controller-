# Frozen evaluation design before model testing

`ci-design-v1`, 7 September 2026. This document and [machine-readable specification](design/evaluation-spec.json) form a **frozen design snapshot**, not approval to execute. Missing acquisition, precision and human-decision gates are explicit. Changing this snapshot requires a new version/hash and an amendment log before evaluation access. No headline run is authorized by this document.

## Questions, feedback and claims

The study asks whether verified change features improve prediction and hypothetical cost decisions beyond history, and whether direct selected-arm learning adds value beyond probability estimation under delayed full-information feedback. It can conclude any of A–F below. It cannot establish production benefit, identify causal deployment effects or demonstrate that CI inherently supplies bandit feedback.

One primary prediction is one eligible first workflow attempt under the [decision contract](decision-feedback-contract.md). Training and outcome-derived histories use that same first-attempt population; do not mix rerun outcomes into primary estimation. The secondary retry study uses separate models with attempt number and all earlier attempt labels. Actions do not alter labels, follow-up, available features or future attempts. Each matured binary label supplies the entire three-action loss vector. All-action observations are correlated transforms of one label; they are not three independent examples. Missingness is common across methods. The existing action-dependent drift simulator is not mixed into this study.

## Ten required methods and additional controls

| Method | Frozen definition / permitted tuning |
|---|---|
| 1. Static rule | Block if project rate>.30 OR (risky path AND (files>=20 OR churn>=1000)); otherwise canary if risky path OR files>=10 OR churn>=300 OR rate>.15; otherwise deploy. Each comparison with null is non-triggering, preserving missingness. Churn is additions+deletions when complete. No fitted parameters. |
| 2. Constant/base-rate probability + expected cost | p0 is the macro-average development-project binary failure fraction available before freeze. No evaluation update. All learners receive the same p0 information. |
| 3. Empirical rate + expected cost | Project-local cumulative observed binary rate; p0 until first eligible label. No tuning. |
| 4. Beta rate + expected cost | Prior alpha=p0*k, beta=(1-p0)*k, k in {1,2,5,10,20,50}; project-local matured updates. Clip development p0 to [1e-6,1-1e-6] for a proper prior, identically for all relevant methods. |
| 5. Rolling rate + expected cost | Windows {7,14,30,90 calendar days, last 20,50,100,200 resolved attempts} crossed with prior strengths {1,2,10}: 24 candidates. Window membership uses availability. |
| 6. Supervised history-only probability | Regularized logistic binary model using H, same transform/optimization schedule as method 7. |
| 7. Supervised verified-context probability | Same logistic family using H plus admitted change/event/workflow features. Repository metadata/identity is a separate pooled sensitivity, not silently added to this within-project study. |
| 8. Full-information action-loss regression | Three regularized linear loss models, each updated from every matured loss vector. Greedy minimum estimated cost; no UCB bonus. Accurately labeled full-information, not standard LinUCB. |
| 9. LinUCB | Selected-arm updates and UCB action selection; same packet and feature encoder. alpha in {0,.25,.5,1,2,4}, lambda in {.1,1,10,100}: 24 candidates. |
| 10. Thompson Sampling | Selected-arm Gaussian linear posterior; same packet/encoder. Prior variance {.1,1,10,100} crossed with noise variance {.01,.05,.1,.5,1,5}: 24 candidates. |

Always-deploy/canary/block are mandatory sanity comparators. Add a fixed-threshold probability mapping (below), matched all-action linear regressors, and optionally a development-specified probability-posterior mean versus sampling diagnostic. A nonlinear supervised sensitivity may be specified and locked during development; it is **not in the current primary ten-method specification** and cannot be introduced after test access. Until a sufficiently strong independently tuned supervised family is tested, conclusions apply to the tested families, not all possible contextual models.

Logistic and full-information regression candidate grid: regularization {.01,.1,1,10,100,1000} crossed with training memory {7,30,90 days, all available history}: 24 candidates. Refit at each distinct label-availability batch using only eligible past rows; no asynchronous computation is credited with future labels. Fixed solver tolerance 1e-8, maximum 1,000 iterations, deterministic initialization; convergence failures are logged and trigger a predeclared fallback to prior predictions, never selective deletion. This is an offline simulation of an online information constraint, not an operational latency claim. The future implementation must validate these solver semantics before GO.

For comparable cold-start prior information, center each action-value learner's reward/loss about its cost under p0, restore that offset at prediction, and initialize residual coefficients at zero. This is a declared initialization for the new study, not a claim of reproducing old headline parameters. All methods reset per project and receive no evaluation outcomes in their initial state. Stochastic streams are keyed by protocol/project/method/seed; the future seed list 0–29 is fixed for Monte Carlo averaging, not permission to execute now. Deterministic methods run once.

## Matched decomposition

1. **Cost mapping:** use exactly the same history-only supervised probabilities to compare a fixed three-tier rule (deploy if p<=.15, canary if .15<p<=.30, block otherwise) with minimum expected cost. The reference thresholds are inherited from the legacy rule and fixed across matrices, not selected to fail on test data. This is a contrast of mappings with frozen predictions, not bandit versus static.
2. **Historical learning:** compare validation-selected empirical/Beta/windowed rate model against fixed p0 under the same expected-cost map. Retain results for every constituent method; do not choose the best one from evaluation outcomes.
3. **Context:** compare the same supervised family with H alone versus H+G, where G contains admitted change and event/workflow descriptors. Report sub-ablations H+event/workflow versus H+change versus complete to distinguish workflow identity from new-change information. The primary admitted set is frozen before validation; a changing feature set does not become a post-hoc explanation.
4. **Architecture:** compare LinUCB and Thompson individually against the contextual probability model, plus the full-information action-loss regression diagnostic. A win under full information is an architecture/regularization/feedback-use result, not proof of an exploration information benefit.

H includes project/workflow rates and counts, repeated-change history, previous workflow duration, available author history and observation coverage/activity. Rate-only and richer-history controls distinguish history richness from current-change context. Project-ID ablation is excluded from the primary per-project-reset design because it is constant there. If a pooled-transfer study is later added, define its pretraining and unseen-project treatment independently.

## Shared preprocessing, tuning and selection

All compared methods within a feature ablation receive identical raw values, missingness indicators, timestamps and encodings. The primary contextual vector uses additions and deletions, excluding redundant total_churn; the latter remains a stored feature and static-rule input. Counts/durations use log1p and development-only location/scale; missing rates use p0 plus a missing mask, other numeric fields use development medians plus masks. All-missing development fields are excluded with reasons. Extension counts use a development-frozen vocabulary with unknown bucket. Categorical workflow identity uses a fixed signed-hash encoder with 32 buckets and protocol-derived hash key; event/branch-class use fixed explicit categories. Publish collisions, dimension, constant columns and scaling. Do not interpret raw workflow/repository numeric IDs as ordered risk features.

Development contains three chronological rolling-origin inner validation blocks. Group repeated repository/tested-SHA instances within fold assignment; groups crossing a fold boundary are excluded from that fold's fit and score and counted in coverage. Fit only on training labels already available by the boundary. Feature transforms are fitted only inside permissible training data for each fold. After development choices are locked, the independent validation repositories receive one full rehearsal/selection pass over the fixed candidate set. Choose each family's candidate by macro-project mean normalized cost under the primary matrix; ties within 1e-12 go to stronger regularization/shorter declared configuration order. Publish all validation configurations and compute times. Fixed methods need not waste runs to consume 24 trials.

Freeze selected parameters and the complete runner before unlocking evaluation. Validation-induced new features, new model classes, altered labels or split rules require an amendment and a fresh validation cohort. Evaluation models start from the same declared development prior information and learn from their own common delayed stream. Raw evaluation labels remain unavailable to the researcher for tuning; prequential model updates are part of the fixed procedure.

All ten methods use the same timestamps, eligibility, project partitions, horizon, cost entries and 30-day resolution limit. Full-information methods may use all losses because every method has that packet. Selected-arm learners' intentional restriction is disclosed. Do not withhold extra labels from one method and describe the result as a fair natural feedback comparison.

## Cost, delay, imbalance and drift scenarios

Primary matrix: deploy(0,10), canary(1,4), block(2,.5). Four secondary one-factor changes vary deploy failure to 5 or 20, or block-success penalty to 1 or 4. Every matrix entry is stored explicitly in JSON; no ratio alone defines a scenario. Conditional probability predictions are reusable unchanged when testing cost mapping. Direct cost learners must be retrained for secondary matrices with parameters selected through the same validation rule; secondary findings are descriptive unless a new confirmatory family is frozen beforehand.

Use actual collector availability for the primary delay condition. A secondary delay perturbation adds a fixed 10 minutes or one hour to **all outcome-dependent source availability**, including history features, then regenerates the shared event stream for all methods. Do not shift model updates while leaving history undelayed. These are artificial observation delays, not intervention effects. Delayed labels crossing the 30-day window receive the same missingness handling for every model. These secondary runs remain unauthorized until GO.

Keep natural class imbalance; never balance the evaluation stream. Report strata fixed from development metadata rather than cutting evaluation projects at a favorable observed prevalence. Time-block analyses can describe heterogeneity; do not call a block “drift” because a method performs poorly there. A new synthetic full-information generator with known context-zero/context-useful cases could support mechanism checks, but must be specified independently; the old action-dependent simulator is not a substitute.

## Estimands and inference

For each project, calculate mean cost over the common resolved binary cohort and normalize by the matrix's largest entry. Report its paired method differences. The primary aggregate weights projects equally; micro/totals and change-cluster-weighted sensitivities are secondary. Report number of rows, distinct SHAs, failures, nonbinary states, capture coverage, unresolved follow-up, first/repeated-change strata, action counts and inference failures. Probability metrics: Brier primary for context, log loss and calibration secondary. Do not convert arbitrary action scores into probabilities for calibration reporting.

Seven primary contrasts under the primary matrix: cost-mapping cost; learned-history versus constant cost; contextual versus history-supervised cost; contextual versus history-supervised Brier; LinUCB versus contextual-supervised cost; Thompson versus contextual-supervised cost; and validation-selected historical rate versus contextual-supervised cost. The last contrast is needed to assess whether simple rate estimators suffice for cost decisions. Select that rate estimator once on validation, never on evaluation. Use paired project differences, two-sided zero-difference tests and Holm family alpha=.05. Report individual 95% t intervals and separate simultaneous Bonferroni t intervals at confidence 1-.05/7 per contrast (df=J-1); label them accurately. These rely on the project-level assumptions below.

Use the simultaneous intervals for practical claims: an improvement is substantial only if its upper bound is below the negative ratified margin. For a bandit-minus-context cost contrast, a lower bound above -delta excludes a bandit benefit of size delta or greater; the whole interval inside [-delta,delta] supports equivalence within that margin. For rate-minus-context cost, an upper bound below delta supports cost noninferiority of the historical estimator, and a whole interval inside [-delta,delta] supports cost equivalence. These are scope-limited statements about hypothetical cost, not predictive equivalence or proof of a zero effect. Context adds substantial predictive and decision value only when both its Brier and cost contrasts satisfy their respective margins. A non-significant difference or a wide interval crossing zero does not justify a no-benefit or sufficiency claim.

Use project-level uncertainty only when the independent project count and effect distribution justify it. Planned analysis uses paired project-mean t intervals plus a project-cluster bootstrap sensitivity (20,000 resamples, seed 4242) after averaging algorithm seeds within project. Do not bootstrap rows as independent. With too few projects/families, present project effects and declare population inference inconclusive. Shared owners/families require a family-cluster sensitivity and can reduce effective replication further. This analysis plan is not a theorem guaranteeing small-sample coverage.

For missing labels, give common coverage and bounded-loss sensitivities: each missing normalized chosen-action loss lies in [0,1], and a paired difference in [-1,1]. Bound the all-eligible mean contrast accordingly; bounds are not point estimates or identification. Conditional-on-resolution findings must remain labeled. A true expected-cost oracle is only available in a correctly specified synthetic process with known risk; a realized-label hindsight oracle is a different reference, not standard regret.

## Allowed conclusions and paper framing

| Outcome | Evidence needed | Permitted claim |
|---|---|---|
| A | Meaningful replicated context gains in Brier and cost | Verified context improved prediction and hypothetical CI decisions in the evaluated cohorts |
| B | Adequate independent replication in prespecified strata | Benefit was restricted to those stated conditions |
| C | Predictive gain plus cost equivalence within the ratified margin; report paired action disagreement descriptively | Context improved prediction without a meaningful hypothetical cost difference under these matrices. Say “rarely changed actions” only against a separately ratified and preregistered disagreement threshold; these are model-estimated expected-cost actions, not a known true-risk oracle |
| D | Context-supervised gains and sufficiently precise no-additional-benefit/inferiority results for selected-arm comparators | Bandits did not add meaningful benefit beyond contextual probability models under this full-information contract |
| E | Strong meaningful context was actually available; the prespecified rate-minus-context cost interval establishes noninferiority/equivalence or superiority | Historical probability estimators sufficed for hypothetical cost decisions within evaluated conditions and tested model families; predictive sufficiency is not established |
| F | Missing useful context, weak independent replication, imprecise or mixed effects | Evidence remains inconclusive |

Outcomes can coexist (A and D, for example). No bandit-positive outcome is required. Provisional framing is **cost-sensitive CI risk prediction with delayed full-information learning**. A deployment-control or bandit-primary framing would need different application evidence. Do not rewrite the manuscript until the data gates, approved experiments and resulting evidence determine the final claim.
