# Feature specification and admission rules

`ci-design-v1`, 7 September 2026. Features are candidates subject to the declared development-data admission rule, not automatically useful because an API exposes them. No new corpus has been collected. Prospective missingness, cardinalities and distributions are therefore **unmeasured**, not zero. The table reports what is actually known from the old 600-row export and how each candidate must be measured in the new corpus.

## Provenance and timing vocabulary

**D** = complete immutable diff whose raw sources were captured by `decision_at`. **M** = trigger/pre-execution metadata captured by decision. **W** = exact workflow version and statically resolvable referenced definitions captured by decision. **R** = timestamped repository metadata snapshot captured by decision. **H** = earlier observations with collector label availability strictly before decision, same repository, and within each originating instance's 30-day follow-up. Commit author dates, provider update timestamps and local extraction time do not substitute for these source times. Pure deterministic transformations may run later against sealed sources; learned transformations use development data only.

All feature values carry definition version, source hashes, maximum dependency availability, completeness state and explicit null reason. The primary study restricts H's outcome dependencies to attempt 1, matching its training/evaluation population; the separate retry cohort admits all earlier attempts. The feature allowlist is `data/research_contract.py::FEATURE_GROUPS`. Branch/ref, SHA, raw actor/author keys and repository ID are provenance/grouping keys unless a row below explicitly admits a derived feature. Missing values remain null with a reason; count zero and false are used only when complete inputs establish absence.

## Exact candidate definitions

In the “existing export” column, **absent** means the required source was not supplied; no prospective distribution is implied. F/R denote Flask/Requests. Current history figures are descriptive counts from the prior audit, not validation of the new collector. Every future row gets the profiling procedure below.

**Pattern version 1:** dependency basenames `package.json`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `pyproject.toml`, `poetry.lock`, `Pipfile`, `Pipfile.lock`, `go.mod`, `go.sum`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `Cargo.toml`, `Cargo.lock`; also `requirements*.txt`. Test patterns: path components exactly `test`, `tests`, `__tests__`, or filenames `test_*.py`, `*_test.py`, `*.test.*`, `*.spec.*`. Configuration: `.github/` prefix, `.gitlab-ci.yml`, `Dockerfile*`, `docker-compose*.yml`, `Makefile`, `tox.ini`, `pytest.ini`, and paths ending `.yaml`, `.yml`, `.toml`, `.ini` (a broad heuristic). Risky prefixes: `.github/`, `deploy/`, `deployment/`, `infra/`, `infrastructure/`, `k8s/`, `migrations/`, `terraform/`. Normalize `/` separators; match paths case-sensitively except the extension feature. Record matches as auditable lineage. These language-biased heuristics must be reported, not described as complete dependency/test/configuration detection.

Diff basis is event-dependent: push tested revision versus first parent; PR head versus captured merge base, with tested merge SHA separately stored. This means the two event cohorts have different change semantics; report separately and adjust with event context. Ambiguous base/head relationships or incomplete diff inventories are missingness, not zero change. Do not retrieve the latest PR file list for an old head. Capture exact workflow ref resolution: `head_sha` is not assumed to be the workflow-definition ref for every event.

## Profiling every feature before admission

The new profiler must emit one row for **every allowlisted feature**, including entirely missing ones, by repository and declared cohort: eligible N; null count/reasons and rate; nonnull count; unique count; fraction at mode; zero/false count separately from missing; numeric min/p01/p25/median/p75/p99/max; categorical counts; distinct SHAs contributing each value; availability-proof coverage; number of dependencies rejected as future/current-attempt; and definition/source hashes. Also report per-workflow and calendar-block diagnostics. For proportions, include the history denominator distribution. No feature-label association or model fit is needed for this collection-quality stage.

The old real export has eight constant-zero numerical fields and rank five including intercept. Those zeros do not qualify as observed negative dependency/test indicators. All new features' missingness and variation remain unmeasured until a data-only development pilot. Do not fabricate prospective cardinality estimates or apply the old four-history-field distribution as if it described the richer corpus.

Admission is locked on development data before validation/evaluation: require a plausible declared risk/workload rationale, authentic availability proof, and a nonconstant value among multiple distinct changes. Core change availability is a dataset GO gate; highly missing optional signals may be excluded. Any optional exclusion must be based on source quality/coverage/variance, not held-out policy gain. Publish the retained/dropped list and reasons. Development-only prediction validation may select model regularization, not retroactively expand the feature catalog after test access. Newly discovered feature ideas require another study/version.

## Encodings and forbidden substitutes

Use train-only numeric transforms (`log1p` for nonnegative counts/durations, development median imputation plus missing indicator; rates use fixed development p0 plus missing indicator). Freeze extension vocabulary and rare-category rules on development; unknowns get explicit buckets. Workflow categories must have a fixed encoder that can represent previously unseen workflow IDs without using their outcomes; the evaluation spec proposes a shared stable signed-hash encoder. Report collision diagnostics. Apply exactly the same feature values/encoder to supervised and direct action-value learners in each matched comparison.

Forbid current outcome/status-progress, current executed tests, current final runtime, observed actual jobs/steps, postdecision workflow logs, incident/rollback fields, future author aggregates and present-day repository snapshots retrojoined to history. `tests_added` is not admitted merely because a column with that name exists: test-file modifications are the supported static feature. “Modules touched” is not claimed without a verified module map; top-level directories are the explicit proxy. A hash/type/timestamp validator cannot verify that a collector mislabeled a post-run payload as a diff; adapter lineage and manual source audits are required before GO.
